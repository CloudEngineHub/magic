# Project files

`list_project_files(project_id, parent_id=None, page_size=50, next_parent_ids=None)` browses one bounded metadata page. It can return file names, project-relative paths, IDs, type, size, and update time when supplied by the service. Pass opaque `next_parent_ids` back unchanged to continue; do not recurse through every directory by default. `get_project_file(file_id)` reads basic metadata for one file. Neither tool provides a browser link or file content.

`prepare_project_files(project_id, file_ids, purpose)` prepares at most ten selected files for reading after a narrow metadata search. Successful entries contain local runtime paths for `read_files` or document tools. Handle each entry's status separately; some files may fail while others succeed. Prepared paths are local, eligible for cleanup after 24 hours on the next preparation, and are not browser links or durable project artifacts. Do not expose signed URLs, object keys, or local runtime paths to users.

For organization, `create_project_directory(project_id, parent_id, name)` creates a folder and `rename_project_file(file_id, name)` renames a file or folder. `copy_project_files(project_id, file_ids, target_project_id, target_parent_id)` leaves the originals; `move_project_files(...)` transfers the originals; `delete_project_files(project_id, file_ids)` removes them using existing product semantics. A request to collect or organize material does not imply permission to move or delete originals. Clarify an unrequested move or deletion and its effect before calling it. The `project_id` is the source project and `target_parent_id` is an exact destination directory ID.

File operations may be asynchronous. If a write returns `batch_key`, call `get_file_batch_status(batch_key)` before reporting completion. Inspect per-file results: partial completion is not an automatic rollback. After a transport timeout, check state before considering another write.
