# Micro App 视觉语言与引导插图规范

**日期：** 2026-07-24

**状态：** 当前视觉方向的可执行规范

**适用范围：** Micro App 落地页、创建流程、功能介绍、空状态、引导页、教学插图、发布物料

**当前实现参考：** `src/pages/superMagic/pages/MicroAppsPage`

---

## 1. 风格定义

这套视觉风格可以概括为：

> 安静的编辑感、真实的产品界面、克制的未来感。

页面首先让用户看到「可以直接描述并做出一个应用」，Agent、Skill、Data、MCP 等能力作为上下文存在，不把技术名词做成同等权重的功能卡片。

视觉上接近现代 AI 创作工具和设计软件的功能介绍页，但不照搬深色科技大屏、玻璃拟态仪表盘或密集功能矩阵。主要通过以下关系建立识别度：

1. 中心区域清晰、稳定，承担标题、说明和主要操作。
2. 四周使用倾斜的产品界面拼贴，表达 Micro App 能连接文件、数据库和外部应用。
3. 大面积暖白、浅灰与深墨色构成基础，仅使用少量蓝、紫和薄荷绿。
4. 无衬线中文标题与衬线斜体英文形成编辑感和人的痕迹。
5. 动画只解释空间层级和交互状态，不持续制造视觉噪声。

## 2. 设计原则

### 2.1 产品结果优先

优先展示做出来的网页应用，而不是抽象展示模型、Agent 或连接协议。

- 主视觉内容：表格、文件、看板、流程、表单、报告、连接器管理页。
- 次要能力提示：Agent、Skill、Data、MCP、Database、File System。
- 不把每个能力做成一张同等尺寸、同等颜色、同等说明长度的卡片。

### 2.2 中心操作优先

标题、说明和输入框是页面最重要的区域。背景元素只能帮助用户理解产品，不得影响输入和阅读。

- 中心安全区占视口宽度约 68%–72%。
- 高对比背景卡片主要停留在左右两侧和上下边缘。
- 背景卡片进入中心区域时，需要通过径向遮罩降低对比度。
- 输入框聚焦后可以略微提高背景可见度，但不能改变布局。

### 2.3 品牌色与状态色分离

品牌色用于说明产品能力和建立页面节奏，状态色用于表达当前结果。两者不能在一张状态插图里平均出现。

- 暖白和浅灰约占 65%–75%。
- 深墨色和中性色约占 15%–22%。
- 普通品牌画面中的强调色约占 6%–12%。
- 状态插图使用中性色加一种语义色，语义色面积不超过约 10%。
- 不因为主页面包含蓝、紫、薄荷绿，就在每个空状态和错误状态中重复这些颜色。
- 同一张状态插图只表达一种状态，不同时展示成功色、警告色和错误色。

### 2.4 真实界面抽象化

背景和引导插图应让用户认出「这是网页应用」，但不需要承载可阅读的真实业务数据。

- 保留浏览器顶部栏、侧边栏、表格、图表、节点和工具按钮等结构。
- 使用短线、色块和几何图形代替大段文字。
- 避免生成无法解释的装饰图形、随机图标和伪代码。
- 每张界面图只表达一个明确功能。

### 2.5 动效服务于层级

动效用于表达前后空间、输入激活和内容进入，不用于展示动画能力。

- 滚动视差只移动背景的前层、后层和遮罩层。
- 常规 UI 入场控制在 0.45–0.9 秒。
- 使用统一缓动：`cubic-bezier(0.22, 1, 0.36, 1)`。
- 支持 `prefers-reduced-motion`，关闭非必要动画。

## 3. 视觉基因

| 维度     | 规则                                         |
| -------- | -------------------------------------------- |
| 气质     | 安静、轻盈、清晰、有编辑感，不做宏大科技叙事 |
| 背景     | 暖白或浅冷灰，不使用纯白大面积直铺           |
| 前景     | 深墨色文字、白色操作面板、低对比边界         |
| 构图     | 中心留白，四周裁切，倾斜界面向画面外延伸     |
| 形状     | 16–28px 圆角为主，少量圆形强调线和胶囊标签   |
| 阴影     | 大范围、低透明度、柔和扩散，不使用硬黑投影   |
| 图形     | 产品界面、表格、图表、连接器、流程节点       |
| 字体关系 | 中文无衬线负责信息，英文衬线斜体负责强调     |
| 动画     | 缓慢进入、轻微位移、前后层不同速度           |
| 信息密度 | 首屏低密度，功能区中密度，单张插图只讲一件事 |

## 4. 色彩规范

### 4.1 基础色

| Token           | 色值                     | 用途                   |
| --------------- | ------------------------ | ---------------------- |
| `canvas`        | `#EDF0F2`                | 浅色页面背景           |
| `canvas-warm`   | `#F8F8F5`                | 中心遮罩和暖白过渡     |
| `ink`           | `#172037`                | 主标题、深色界面卡片   |
| `surface`       | `#FFFFFF`                | 输入框、浅色卡片、面板 |
| `surface-muted` | `#F1F2F5`                | 界面侧栏、次级区域     |
| `line`          | `rgba(23, 32, 55, 0.10)` | 浅色边框和分隔线       |
| `text-muted`    | `rgba(23, 32, 55, 0.60)` | 正文、副标题           |

### 4.2 品牌强调色

| Token           | 色值      | 用途                               |
| --------------- | --------- | ---------------------------------- |
| `blue`          | `#2F73FF` | 数据分析、核心操作、高对比主卡     |
| `violet`        | `#7869E6` | Agent、Skill、自动化流程           |
| `violet-active` | `#6254D9` | 聚焦状态、能力标签激活             |
| `mint`          | `#7BE8AE` | 最终产物强调、连接成功、轻量正反馈 |
| `mint-surface`  | `#DFF8E9` | 浅色数据库或连接状态卡片           |
| `dark-panel`    | `#172037` | MCP、连接器、技术能力界面          |

品牌强调色不是状态色。蓝色、紫色和薄荷绿可以共同出现在产品能力介绍中，但错误、空状态和加载插图不应直接复制这组配色。

### 4.3 状态色

| 状态       | 主色      | 浅色表面  | 使用场景                           |
| ---------- | --------- | --------- | ---------------------------------- |
| 中性空状态 | `#8390A6` | `#F1F3F6` | 暂无项目、无搜索结果、尚未配置     |
| 加载中     | `#5B7FEA` | `#EDF2FF` | 获取列表、生成中、同步中           |
| 可恢复异常 | `#D79B3E` | `#FFF2DC` | 网络失败、加载失败、可重试操作     |
| 阻断错误   | `#D85A54` | `#FDECEA` | 权限拒绝、数据损坏、不可继续的错误 |
| 成功完成   | `#58C98B` | `#E5F7EC` | 发布成功、连接成功、生成完成       |

状态配色规则：

- 状态插图以 `ink`、白色和浅灰为主体，只加入一种状态色。
- 可恢复异常优先使用琥珀色，不使用大面积红色，避免制造不可恢复的感觉。
- 红色只用于确实阻止用户继续的错误，不用于普通接口超时和列表加载失败。
- 薄荷绿只表达完成、恢复或连接成功，不作为所有插图的默认装饰色。
- 紫色主要表达 Agent、Skill 和自动化能力，不承担错误或成功状态。
- 同一状态的图标、轮廓、背景光和按钮反馈使用同一色相，不再分别使用蓝、紫和绿。

### 4.4 深色模式

- 页面背景使用 `#101116`。
- 主要面板使用 `rgba(9, 9, 11, 0.72)`，配合轻微背景模糊。
- 白色文字避免全量使用 100% 不透明度，正文建议 55%–72%。
- 背景拼贴整体透明度应降低到浅色模式的约 20%–35%。
- 薄荷绿和紫色可以保留色相，但减少发光和高亮面积。

### 4.5 禁止用法

- 不使用彩虹渐变作为大面积背景。
- 不同时使用超过三个高饱和度强调色。
- 状态插图不同时使用两种以上语义色。
- 不使用霓虹描边、外发光文字和强烈蓝紫光晕。
- 不用纯黑代替 `ink`，避免页面过硬。

## 5. 排版规范

### 5.1 能力路径标签

示例：`AGENT / SKILL / DATA / MCP → MICRO APP`

- 字体：等宽字体。
- 桌面字号：10px。
- 移动端字号：8px。
- 字重：600。
- 字间距：桌面 `0.18em`，移动端 `0.12em`。
- 使用全大写英文。
- 默认颜色：`ink / 45%`。
- 最终产物 `MICRO APP` 使用完整 `ink`。
- 聚焦时前置能力可切换为 `violet-active`，但不增加新的标签。

### 5.2 主标题

- 桌面字号：54px，宽屏可到 64px。
- 移动端字号：36px。
- 字重：600。
- 行高：1–1.04。
- 字间距：`-0.05em` 到 `-0.055em`。
- 中文使用项目默认无衬线字体。
- 最终产物词可以使用衬线、斜体和较轻字重。
- 标题尽量保持一句话，避免主标题和副标题重复解释相同内容。

### 5.3 手绘强调

`Micro App` 等最终产物词可以使用薄荷绿色的不规则椭圆路径强调。

- 填充：`rgba(123, 232, 174, 0.14)`。
- 描边：`#7BE8AE`。
- 描边宽度：约 5px。
- 轮廓应略微不对称，避免标准几何椭圆。
- 只强调一个词，不同时给多个短语加圈、下划线或高亮底色。

### 5.4 正文和说明

- 桌面副标题：17px / 28px。
- 移动端副标题：14px / 24px。
- 颜色：`ink / 60%–62%`。
- 单行或两行优先，最大宽度约 768px。
- 文案使用普通口语，不使用技术白皮书式说明。

### 5.5 卡片文字

- 标题：15px / 600，轻微负字距。
- 描述：12px / 20px，最多两行。
- 元信息：12px，弱化显示。
- 状态标签：10px，使用中性色胶囊，不抢标题。

## 6. 空间与布局

### 6.1 桌面首屏

- Hero 最小高度：页面可视区域的 70%。
- 内容最大宽度：1480px。
- 标题最大宽度：1080px。
- 输入框最大宽度：896px。
- 标题到副标题：约 24px。
- 副标题到输入框：约 28px。
- 首屏左右内边距：48px。
- 中心内容垂直居中，不将标题贴近页面顶部。

### 6.2 普通桌面背景画布

适用于有效视口宽度小于 1536px：

- 设计画布：1800 × 900px。
- 整体缩放：0.72。
- 整体旋转：-14°。
- 左右主卡分别露出约 180–240px。
- 高对比卡片至少展示自身面积的 35%–50%。

### 6.3 宽屏背景画布

适用于有效视口宽度大于等于 1536px：

- 设计画布：2320 × 1320px。
- 整体缩放：0.76。
- 整体旋转：-14°。
- 卡片可以更分散，但不能完全离开可视区域。

### 6.4 移动端

- Hero 最小高度：可视区域的 70%。
- 页面左右内边距：16px。
- 标题最大宽度：390px。
- 副标题最大宽度：350px。
- 背景画布：760 × 900px。
- 整体缩放：0.72。
- 整体旋转：-12°。
- 输入框宽度使用可用区域的 100%。
- 左右卡片需要保留可辨识结构，不能只露出一个颜色碎片。
- 中心约 88vw 范围内避免高对比装饰。

## 7. 背景产品拼贴

### 7.1 拼贴结构

桌面端建议使用 8 张界面卡片，移动端建议使用 5 张：

- 后层：文件、文档、表格、数据库等浅色界面。
- 前层：数据分析、MCP 连接器、Agent 流程等高对比界面。
- 卡片在四周被容器裁切，让画面看起来仍向外延伸。
- 卡片之间保留足够空隙，不做密集瀑布流。

### 7.2 卡片外观

- 圆角：28px。
- 边框：1px，透明度 10%–30%。
- 阴影：`0 24px 70px rgba(23, 32, 55, 0.12)`。
- 顶栏包含三个低对比圆点和一个 16px 功能图标。
- 浅色卡片以白色为主，深色卡片使用 `ink`。
- 不使用真实浏览器品牌、网站 Logo 和复杂地址栏。

### 7.3 推荐界面内容

1. 数据分析：柱状图、指标区、趋势卡片。
2. 表格数据库：侧栏、字段列、状态色块。
3. 文件文档：标题、段落、附件摘要。
4. Agent 流程：节点、连接线、成功状态。
5. MCP 连接器：3 × 2 应用连接矩阵。
6. 审批表单：字段、步骤、状态和提交操作。
7. 发布预览：桌面端和移动端 Micro App 预览。
8. 外部应用：钉钉、飞书、GitHub 等连接关系的抽象表达。

### 7.4 中心遮罩

浅色模式使用暖白径向渐变：

```css
radial-gradient(
  ellipse at center,
  rgba(248, 248, 245, 0.99) 0%,
  rgba(248, 248, 245, 0.97) 28%,
  rgba(248, 248, 245, 0.82) 40%,
  rgba(248, 248, 245, 0.20) 68%,
  transparent 84%
)
```

遮罩作用是建立阅读区，不是将背景完全抹掉。普通桌面下，左右两侧仍应看见卡片轮廓和部分内部结构。

## 8. 核心 UI 组件

### 8.1 创建输入框

输入框是首屏唯一的主要操作，不额外增加同等级 CTA。

- 圆角：16px。
- 背景：白色；深色模式使用半透明黑色。
- 边框：白色或低透明度边界。
- 阴影：大范围柔和阴影，建立悬浮层级。
- 桌面最小编辑高度：92px。
- 移动端最小编辑高度：70px。
- 工具按钮圆角：8px。
- 工具顺序保持稳定：联网、MCP、上传、分隔线、语音、发送。
- 聚焦反馈优先使用背景可见度、边框和阴影变化，不移动输入框。

当前阴影参考：

```css
box-shadow:
	0 28px 90px rgba(35, 32, 53, 0.18),
	0 2px 10px rgba(35, 32, 53, 0.05),
	inset 0 1px 0 rgba(255, 255, 255, 0.92);
```

### 8.2 Micro App 卡片

- 比例：16:10。
- 圆角：16px。
- 默认阴影：`0 12px 36px rgba(24, 24, 35, 0.06)`。
- Hover 阴影：`0 28px 72px rgba(24, 24, 35, 0.15)`。
- Hover 位移：向上 7px，可附加约 1.4° 的轻微 3D 倾斜。
- 封面优先使用真实 Micro App 截图。
- 没有封面时使用抽象产品界面，不使用通用渐变占位图。

### 8.3 次级列表与筛选

- 功能区使用白色背景和普通内容密度，与首屏形成节奏变化。
- 搜索框高度 36px。
- Tabs 使用中性浅灰底，选中状态以白色表面和文字权重表达。
- 不把蓝色用于所有交互控件，避免破坏首屏的克制色彩比例。

## 9. 动效规范

### 9.1 首屏进入

| 元素     | 初始状态                            | 时长  |
| -------- | ----------------------------------- | ----- |
| 能力路径 | `opacity: 0; x: -12px`              | 0.55s |
| 主标题   | `opacity: 0; y: 24px`               | 0.72s |
| 副标题   | `opacity: 0; y: 14px`               | 0.70s |
| 输入框   | `opacity: 0; y: 20px; scale: 0.985` | 0.80s |
| 手绘圈线 | `pathLength: 0 → 1`                 | 0.90s |

所有元素使用同一缓动，不同时加入模糊、旋转和弹簧回弹。

### 9.2 滚动视差

桌面端：

- 后层：`x +38px / y -72px`。
- 前层：`x -46px / y -112px`。
- 中心遮罩：`y -48px / scale 1.08`。

移动端：

- 后层：`x +16px / y -42px`。
- 前层：`x -20px / y -68px`。
- 中心遮罩：`y -48px / scale 1.08`。

实现要求：

- 使用 ScrollTrigger 的 `scrub: 1`。
- 只动画 `transform` 和必要的 `opacity`。
- 只给实际参与动画的层添加 `will-change: transform`。
- 组件卸载时清理时间线和 ScrollTrigger。
- 开启减少动态效果时不创建滚动动画。

### 9.3 交互反馈

- Hover 反馈在 150–300ms 内完成。
- 页面级进入动画不重复播放。
- 点击反馈可使用 `scale: 0.985`，不使用明显弹跳。
- 成功状态优先使用薄荷绿、状态文字和轻微位移，不使用烟花或粒子动画。

## 10. 引导插图规范

### 10.1 插图目标

引导插图应帮助用户快速识别功能关系，而不是作为纯装饰海报。

每张图只回答一个问题：

- Micro App 能连接什么？
- Agent 如何把一句话变成应用？
- Skill、Data 和 MCP 在哪里参与？
- 文件、数据库和外部应用如何进入同一个应用？
- 创建、编辑、发布分别发生什么？

### 10.2 标准构图

- 背景使用 `canvas` 或 `canvas-warm`。
- 主体是一张清晰的产品界面卡片。
- 周围最多放置 3–5 个关联界面或能力节点。
- 主体占画面 45%–62%。
- 四周元素可以裁切，但关键关系线不能被裁掉。
- 使用 12°–16° 的统一倾斜，不给每张卡片随机角度。
- 保留 28%–40% 的干净留白，方便叠加标题或步骤说明。

### 10.3 图形语言

- 使用界面面板、浏览器窗口、表格、文件卡片和连接节点。
- 图标使用 1.5–2px 线宽的简洁线性图标。
- 连接关系使用 1px–2px 低对比线条。
- 空状态使用灰蓝色，只表达「尚未发生」。
- 加载中使用冷蓝色，适合循环、扫描和进度关系。
- 可重试的加载失败使用琥珀色，适合刷新、暂停和暂时中断。
- 阻断错误使用低饱和红色，且只标出一个关键错误节点。
- 成功状态使用薄荷绿，适合完成、连接和发布结果。
- Agent 或 Skill 介绍可以使用紫色，但不能把紫色当成通用状态色。
- 一张状态插图只使用一种上述语义色，其余界面保持白色、灰色和深墨色。
- 状态插图在页面中承担辅助说明，不高于标题和主要操作的视觉层级。
- 常规桌面状态插图宽度控制在 120–156px；只有「正在制作」等主预览状态可以放大到 280px。
- 深墨色实心面积不超过插图的 5%，优先使用浅灰线框和低透明度结构。
- 状态色面积控制在 5%–8%，不使用覆盖标题区域的大范围状态色光晕。
- 状态插图不叠加多层阴影；界面与状态徽记最多保留一层轻阴影。

### 10.4 推荐比例

| 场景         | 比例       | 用途                 |
| ------------ | ---------- | -------------------- |
| 功能介绍横幅 | 16:9       | 页面段落、发布说明   |
| 引导步骤图   | 4:3        | Tour、弹窗、教学页   |
| 空状态插图   | 1:1 或 5:4 | 列表空状态、错误提示 |
| 移动端引导   | 3:4        | 移动端全屏介绍       |
| 小型能力图标 | 1:1        | 功能入口、步骤节点   |

### 10.7 状态插图组件

代码入口：

```text
src/pages/superMagic/components/MicroAppStateIllustration
```

统一组件 `MicroAppStateIllustration` 接受 `state`、`size`、`animated`、`label` 和 `testId`。业务代码优先使用具名组件，避免在页面中重复维护 SVG：

| 组件                                | 状态                 | 语义色   |
| ----------------------------------- | -------------------- | -------- |
| `MicroAppEmptyIllustration`         | 暂无微应用、预览为空 | 中性灰蓝 |
| `MicroAppBuildingIllustration`      | 正在制作             | 冷蓝     |
| `MicroAppConfirmIllustration`       | 等待用户确认方案     | 克制紫   |
| `MicroAppSearchEmptyIllustration`   | 搜索无结果           | 中性灰蓝 |
| `MicroAppRetryIllustration`         | 可恢复连接或加载异常 | 琥珀色   |
| `MicroAppPermissionIllustration`    | 权限阻断             | 低饱和红 |
| `MicroAppPublishedIllustration`     | 发布成功             | 薄荷绿   |
| `MicroAppDatabaseEmptyIllustration` | 数据库无表或暂无数据 | 中性灰蓝 |

组件默认作为静态装饰图并从无障碍树中隐藏。插图本身需要传达额外信息时，传入 `label`；页面已有标题和说明时不要重复设置。只有加载和生成过程按需开启 `animated`，其他状态不默认循环播放。循环动效必须通过组件内部的 `prefers-reduced-motion` 处理，不由业务页面重复判断。

## 11. 不同场景的应用方式

| 场景       | 视觉结构                         | 内容重点                   |
| ---------- | -------------------------------- | -------------------------- |
| 首次进入   | 中心标题与操作，四周产品拼贴     | 一句话创建 Micro App       |
| 功能介绍   | 左文右图或上文下图               | 单项能力和用户收益         |
| 分步引导   | 单张主界面加 1–3 个标注          | 当前步骤需要点击的位置     |
| 空状态     | 小型界面插图加一句操作建议       | 下一步动作，不解释完整产品 |
| 数据库介绍 | 表格主界面加文件和应用连接       | 数据如何被应用使用         |
| MCP 介绍   | 连接器矩阵加中心 Micro App       | 外部能力如何进入应用       |
| 发布流程   | 编辑器、预览、公开页面三段关系   | 从创建到分享的过程         |
| 可恢复异常 | 中性界面加单个琥珀色刷新节点     | 原因、影响和恢复操作       |
| 阻断错误   | 中性界面加单个低饱和红色错误节点 | 无法继续的原因和解决方式   |

不要在所有场景都复制首屏的大标题、手绘圈和八张拼贴卡片。应复用色彩、构图关系、界面语言和动效节奏，而不是复制完整布局。

## 12. 反例

以下做法不属于这套视觉语言：

- 使用六张同尺寸功能卡片解释 Agent、Skill、Database、MCP 等概念。
- 用大量文案直接写在背景插图中。
- 使用通用 AI 机器人、魔法棒、芯片和大脑图标作为主视觉。
- 用蓝紫渐变覆盖整个页面。
- 同一屏同时出现强阴影、发光描边、玻璃拟态和 3D 图标。
- 背景卡片完全不可见，或进入中心遮挡标题和输入框。
- 为了高级感使用过小文字、低对比正文或过大的空白。
- 移动端简单裁切桌面画面，导致关键卡片消失。
- 每个 Hover 都旋转、缩放、发光，造成交互噪声。

## 13. 验收清单

### UI 页面

- [ ] 用户第一眼能找到主要操作。
- [ ] 标题和说明在浅色、深色模式下都清晰可读。
- [ ] 背景能看出是不同类型的网页应用，而不是抽象色块。
- [ ] 普通桌面和宽屏分别检查过卡片可见面积。
- [ ] 移动端左右至少能看到两张可辨识的界面卡片。
- [ ] 高饱和色面积没有超过画面的约 18%。
- [ ] 状态插图只使用一种与语义匹配的状态色。
- [ ] 同一层级的圆角、边框和阴影保持一致。
- [ ] 输入框工具顺序和交互状态稳定。
- [ ] 动画关闭后，页面结构和信息层级仍然成立。

### 引导插图

- [ ] 每张图只表达一个核心关系。
- [ ] 主体界面能够被识别为 Micro App 或相关工具。
- [ ] 文件、数据库、Agent、Skill、MCP 的关系有明确方向。
- [ ] 没有无意义的装饰节点和随机图标。
- [ ] 没有真实品牌 Logo、敏感数据和不可控文字。
- [ ] 空、加载、异常、错误和成功没有复用同一套强调色。
- [ ] 缩小到实际展示尺寸后，主体结构仍可辨识。
- [ ] 留白足够承载标题、步骤或操作按钮。
